# Quick Task 261018-d0z: Fix the relative auth base URL that breaks the customer and lanka-mahal builds

## Origin

CI has been red on `main` since at least 2026-09-24 and blocked PR #2. The failure is:

```
Error occurred prerendering page "/notifications/settings".
[Error [BetterAuthError]: Invalid base URL: /api/auth. Please provide a valid base URL.]
  code: 'ERR_INVALID_URL'
Failed: lanka-mahal#build
```

Reproduced on `ceafdad` (main tip, run 38729455489) and on PR #2 (run 39094844317) —
identical error, so this is pre-existing and not caused by the retheme work.

## Root cause

`apps/customer/lib/auth-client.ts` and `apps/lanka-mahal/lib/auth-client.ts` are the
**only two files in the repo** that fall back to a relative URL:

```ts
baseURL: process.env.NEXT_PUBLIC_API_URL
  ? `${process.env.NEXT_PUBLIC_API_URL}/api/auth`
  : '/api/auth',        // ← relative → invalid
```

`createAuthClient` requires an absolute URL and throws at module evaluation when given
`/api/auth`. `.github/workflows/ci.yml` sets no environment variables, so
`NEXT_PUBLIC_API_URL` is undefined during the CI build and every prerender that imports
the auth client dies.

Every other consumer in the codebase already uses an **absolute** fallback:

| File | Fallback |
|---|---|
| `apps/customer/lib/api.ts` | `?? 'http://localhost:3001'` |
| `apps/lanka-mahal/lib/api.ts` | `?? 'http://localhost:3001'` |
| `apps/admin/lib/api.ts` | `\|\| 'http://localhost:3001'` |
| `apps/*/next.config.ts` | `?? 'http://localhost:3001'` |
| `apps/*/vitest.config.ts` | injects `NEXT_PUBLIC_API_URL` explicitly |

The auth clients are the outliers, so this is a convention violation rather than a
missing CI variable.

## Task 1 — Replace the relative auth base URL fallback with the repo's absolute fallback

**Files:** `apps/customer/lib/auth-client.ts`, `apps/lanka-mahal/lib/auth-client.ts`

**Problem:** the relative `'/api/auth'` fallback produces an invalid URL for
`createAuthClient` whenever `NEXT_PUBLIC_API_URL` is unset, failing the build at the
`/notifications/settings` prerender.

**Action:** hoist the base URL to a module constant using the same
`?? 'http://localhost:3001'` fallback as `lib/api.ts` in each app, then build the auth
base URL from it:

```ts
const API_URL = process.env.NEXT_PUBLIC_API_URL ?? 'http://localhost:3001';

export const authClient = createAuthClient({
  baseURL: `${API_URL}/api/auth`,
});
```

Apply identically to both files. They are byte-identical today, so the change is too.

**Verify:** with `NEXT_PUBLIC_API_URL` unset, `pnpm --filter customer build` and
`pnpm --filter lanka-mahal build` both complete without the BetterAuthError.

**Done:** both portal apps build with no environment variables set.
