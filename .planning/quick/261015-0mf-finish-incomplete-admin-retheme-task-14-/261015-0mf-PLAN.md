# Quick Task 261015-0mf — Plan: Graphite & Signal retheme + close retheme task 14

Per the locked CONTEXT: replace the admin's emerald-on-slate token values with the
Graphite & Signal direction (true neutral graphite + one signal cyan-teal accent), flatten
every surface (shadows, glow, blur, mesh all go), evolve the shell, move type to IBM Plex,
then complete the owed visual pass from spec `0001-a` task 14 and close the stale
paperwork. Every role the direction does not name is **derived** — dropping a role or
leaving a stale emerald/Octet value is a failure.

Palette spine: graphite `#f5f5f5` canvas / `#0d0d0d` dark canvas · `#141414` ink ·
accent `#4f46e5` light / `#a5b4fc` dark.

> **Revision note (2026 10 15/16).** The accent in this plan was first written as signal
> cyan-teal (`#0e7490` / `#4dd4e8`). During the build the user changed it to **signal violet
> `#4f46e5` / `#a5b4fc`**, which flipped `--info` back to cyan (`#0e7490` / `#22d3ee`) — the
> opposite of what Task 1 below says. Task 1's cyan derivation is kept as written history; the
> shipped values are in `packages/ui/src/tokens.css` and in `apps/admin/DESIGN.md`, and the
> contrast verifier was re-run against the violet values (zero failures, both themes). Two
> further amendments: card radius tightened (`rounded-xl` → `rounded-md`, modals `rounded-2xl`
> → `rounded-lg`), and the topbar was redesigned as a flat hairline instrument bar with square
> icon controls and cluster dividers, plus a View Transitions cross-fade on theme switch.

Known trap from the spec: `tracking-timeline.tsx` still carries pre-retheme values
(`#22c55e`, `#ef4444`, `#9ca3af`, `#f59e0b`) even though spec task 9 is annotated built —
do not trust that annotation for this file; remap every hex in its `DOT_COLORS`.
