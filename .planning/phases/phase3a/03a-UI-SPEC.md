| 2 (sm) | 8px | Compact element spacing, badge padding |

| 5 (lg) | 20px | Section inner gaps |

| 10 (3xl) | 40px | Marketing section breaks |

## Interaction Contract

### Scroll-Triggered Reveal Animations
- **Implementation:** Lightweight Intersection Observer (no framer-motion — minimal dependency per design taste)
- **Target:** All landing sections (Hero → Stats → Features → HowItWorks → Testimonials → FAQ → CTA)
- **Animation:** `fade-up` — opacity 0→1 + translateY(24px)→translateY(0) over 500ms ease-out
- **Stagger:** Child elements within a section stagger by 80ms delay per child (e.g., feature cards stagger)
- **Threshold:** `rootMargin: '-80px'` (trigger when section is ~80px from viewport)
- **CSS keyframes** already exist in globals.css (`@keyframes fade-up`). Apply via `animate-[fade-up_0.5s_ease-out]` class added by observer.

### Hero Section Interaction
- **Tracking form:** Real-time input with submit button; loading state via `isPending`; error message below form
- **Search result card:** Slides in below the form on successful search; shows tracking details + timeline + claim option (if authenticated)
- **Mobile:** Same layout, full-width input + button stack at `sm:flex-row`

### PortalNav Scroll Behavior
- **Initial state:** Transparent background, white text, no border
- **Scrolled (y > 20):** `bg-surface/90 backdrop-blur-md border-b border-border`, dark text
- **Menu open (mobile):** Same as scrolled state
- **Transition:** 300ms all-ease (existing, keep as-is)

### Dashboard Interactions
- **KPI cards:** Hover lift (`hover:-translate-y-0.5 hover:shadow-md`) — already implemented
- **Recent shipments:** Row hover (`hover:bg-background`), clickable → `/track/[trackingNo]`
- **Alerts:** Warning banner with amber tint; no dismiss needed (auto-resolves)
- **Error state:** Shows icon + message + "Try again" button that calls `refetch()`
- **Loading skeleton:** Pulse animation on 4 card placeholders + 3 row placeholders

### Footer
- **Back-to-top:** Smooth scroll to top on click
- **Links:** Hover underline accent
- **Minimal aesthetic:** Single column on mobile, 3-4 columns on desktop with `text-sm text-muted`, border-t separator

## States & Loading Contract

### Landing Page (anonymous)

| State | Behavior |
|-------|----------|
| Initial load | Hero CTA form visible, tracking result area empty. All sections visible immediately. Scroll reveals animate in. |
| Tracking lookup pending | Submit button shows spinner (`isPending` + `RefreshCw animate-spin`), input disabled |
| Tracking result found | Result card slides in below form with tracking info + timeline + claim option |
| Tracking not found | `text-danger` error message below form: "{tracking number} not found" |
| Tracking error (network) | `text-danger` error: "Could not check tracking. Please try again." |
| Claim pending | Claim button shows spinner "Claiming..." |
| Claim success | Green checkmark + "Shipment claimed!" message replaces claim button |
| Claim error | Red error text below claim button |
| Edge: empty input submitted | No action (submit disabled when `!trackingNo.trim()`) |

### Dashboard (authenticated)

| State | Behavior |
|-------|----------|
| Loading | `DashboardSkeleton` — 4 card-shaped pulse placeholders in 2×2 grid + 3 row-shaped pulse placeholders |
| Empty (no shipments) | KPI grid hidden. "No shipments yet" heading + "Enter a tracking number above to get started..." body + link to tracking |
| Data | KPI grid (Total, In Transit, Delivered, Exceptions if >0) + Recent Shipments list + Alerts banner (if any) |
| Error | Error state with `PackageSearch` icon + "Failed to load dashboard" + "Try again" button |
| Auth loading | `null` (no flash) — guarded by `if (!session) return null` |
| Unauthenticated | Redirect to `/login` via `useEffect` + `router.replace` |

## Hero Section Full-Width Fix

**Problem:** Current hero uses `w-screen left-[calc(-50vw+50%)] -mt-14` to break out of the `max-w-5xl` parent container — fragile on scrollbar widths and viewport edge cases.

**Solution:** Move the landing page OUT of the `(portal)` route group layout for the hero section, so it's not constrained by `max-w-5xl`.

Architecture:
1. The `PublicLanding` component on the home page (`app/page.tsx` at root, NOT in `(portal)`) renders without the max-width wrapper
2. After the hero section, the rest of the landing sections use a shared `max-w-5xl mx-auto px-4` container
3. Authenticated pages remain in `(portal)` with the existing max-width layout

Alternative (simpler): Keep in `(portal)` but have the HeroSection render its own full-width `<section>` that ignores the parent max-width via negative margin approach. If alternative is chosen, the previous `w-screen` hack MUST be replaced with a stable technique:
  ```tsx
  <section className="relative -mx-4 sm:-mx-6 lg:-mx-8">
    {/* hero content */}
  </section>
  ```
  ...or the wrapper approach:
  ```tsx
  <div className="w-full" style={{ width: '100vw', marginLeft: 'calc(-50vw + 50%)' }}>
    <div className="mx-auto max-w-5xl px-4">
      {/* hero content */}
    </div>
  </div>
  ```

**Preferred:** Create a separate root-level layout for the landing page (`app/lading-page-layout.tsx`?) that the home page uses, bypassing the max-width wrapper. The `(portal)` layout remains for authenticated pages.
