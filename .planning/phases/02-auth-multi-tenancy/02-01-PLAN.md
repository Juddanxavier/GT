# Plan 02-01: Database Schema — Tenants, Branches, User Extension

## Objective

Replace the placeholder Drizzle schema with real database tables for multi-tenant auth: tenants, branches, tenant_domains, and extend the user table with tenantId, role, and branchId. This is the foundation for all multi-tenant operations in the system.

**Purpose:** Every feature in Phase 2+ depends on the DB schema being correct. Getting tenants, branches, roles, and user extensions right now prevents cascading data model changes later.

**Output:** Complete Drizzle schema with all Phase 2 tables, plus a migration applied to NeonDB.

  <name>Task 1: Write complete Drizzle schema with tenants, branches, tenant_domains, and extended user table</name>
  <files>apps/api/src/db/schema.ts</files>
  <action>
    Replace the entire `apps/api/src/db/schema.ts` with the following. This file defines all tables needed for Phase 2:

    1. **tenants** table — Organization/company that owns data
       - id: uuid PK default gen_random_uuid()
       - name: varchar(255) not null
       - slug: varchar(100) not null unique (e.g., "gajan-india", "gajan-sri-lanka")
       - createdAt: timestamp default now() not null
       - updatedAt: timestamp default now() not null

    2. **branches** table — Locations within a tenant
       - id: uuid PK default gen_random_uuid()
       - name: varchar(255) not null
       - phone: varchar(50)
       - email: varchar(255)
       - address: text
       - tenantId: uuid FK → tenants.id not null
       - createdAt: timestamp default now() not null
       - updatedAt: timestamp default now() not null

    3. **tenant_domains** table — Maps domains to tenants for portal resolution
       - id: uuid PK default gen_random_uuid()
       - domain: varchar(255) not null unique (e.g., "india.gajantraders.com")
       - tenantId: uuid FK → tenants.id not null
       - createdAt: timestamp default now() not null

    4. **user** table — Better Auth core table + our custom fields
       - id: text PK (Better Auth uses text IDs, not uuid — matches `crypto.randomUUID()`)
       - name: text not null
       - email: text not null unique
       - emailVerified: boolean not null default false
       - image: text
       - **tenantId**: text FK → tenants.id (nullable — superadmin may not belong to a tenant)
       - **role**: text not null default 'customer' with CHECK(role in ('superadmin','tenant-admin','staff','customer'))
       - **branchId**: text FK → branches.id (nullable — customer/superadmin have no branch)
       - createdAt: timestamp not null
       - updatedAt: timestamp not null

       Use `text` type for all Better Auth fields to match what the library expects (not `varchar` — Better Auth generates IDs as random strings, not UUIDs).

    5. **session** table — Better Auth core
       - id: text PK
       - userId: text FK → user.id not null
       - token: text not null unique
       - expiresAt: timestamp not null
       - ipAddress: text
       - userAgent: text
       - createdAt: timestamp not null
       - updatedAt: timestamp not null

    6. **account** table — Better Auth core (OAuth + credential accounts)
       - id: text PK
       - userId: text FK → user.id not null
       - accountId: text not null
       - providerId: text not null
       - accessToken: text
       - refreshToken: text
       - accessTokenExpiresAt: timestamp
       - refreshTokenExpiresAt: timestamp
       - scope: text
       - idToken: text
       - password: text
       - createdAt: timestamp not null
       - updatedAt: timestamp not null

    7. **verification** table — Better Auth core (email verification, password reset)
       - id: text PK
       - identifier: text not null
       - value: text not null
       - expiresAt: timestamp not null
       - createdAt: timestamp not null
       - updatedAt: timestamp not null

    **Critical implementation notes:**
    - Use `text` (not `varchar`) for Better Auth tables — Better Auth generates IDs as hex strings, not UUIDs. Using `uuid` type would cause type mismatches with the library.
    - For our custom `tenants`, `branches`, `tenant_domains` tables, use `uuid` PK with `defaultRandom()` since they're managed by our code.
    - The role check constraint must be: `CHECK(role IN ('superadmin', 'tenant-admin', 'staff', 'customer'))`. Don't use a Drizzle enum because PostgreSQL enums are hard to migrate later.
    - Add `updatedAt` triggers must be handled manually in Drizzle (no auto `updatedAt`). We'll use `.onUpdateNow()` from `drizzle-orm/pg-core` on timestamp columns where available, or handle updatedAt manually.
    - Use `onDelete: 'cascade'` on FK references where appropriate (session.userId, account.userId).
    - Use `onDelete: 'set null'` on tenantId if tenant is deleted (we don't want to lose user accounts).
    - Use `onDelete: 'restrict'` on branch tenantId (can't delete tenant with branches).

    Here is the complete schema template:

    ```typescript
    import {
      pgTable,
      text,
      uuid,
      varchar,
      timestamp,
      boolean,
      uniqueIndex,
      index,
    } from 'drizzle-orm/pg-core';

    // ── Custom Multi-Tenant Tables ──

    export const tenants = pgTable('tenant', {
      id: uuid('id').defaultRandom().primaryKey(),
      name: varchar('name', { length: 255 }).notNull(),
      slug: varchar('slug', { length: 100 }).notNull().unique(),
      createdAt: timestamp('created_at').defaultNow().notNull(),
      updatedAt: timestamp('updated_at').defaultNow().notNull(),
    });

    export const branches = pgTable('branch', {
      id: uuid('id').defaultRandom().primaryKey(),
      name: varchar('name', { length: 255 }).notNull(),
      phone: varchar('phone', { length: 50 }),
      email: varchar('email', { length: 255 }),
      address: text('address'),
      tenantId: uuid('tenant_id')
        .notNull()
        .references(() => tenants.id, { onDelete: 'restrict' }),
      createdAt: timestamp('created_at').defaultNow().notNull(),
      updatedAt: timestamp('updated_at').defaultNow().notNull(),
    });

    export const tenantDomains = pgTable('tenant_domain', {
      id: uuid('id').defaultRandom().primaryKey(),
      domain: varchar('domain', { length: 255 }).notNull().unique(),
      tenantId: uuid('tenant_id')
        .notNull()
        .references(() => tenants.id, { onDelete: 'cascade' }),
      createdAt: timestamp('created_at').defaultNow().notNull(),
    });

    // ── Better Auth Core Tables (with custom extensions) ──

    export const user = pgTable(
      'user',
      {
        id: text('id').primaryKey(),
        name: text('name').notNull(),
        email: text('email').notNull().unique(),
        emailVerified: boolean('email_verified').notNull().default(false),
        image: text('image'),
        // Custom multi-tenant fields
        tenantId: uuid('tenant_id').references(() => tenants.id, {
          onDelete: 'set null',
        }),
        role: text('role')
          .notNull()
          .default('customer'),
        branchId: uuid('branch_id').references(() => branches.id, {
          onDelete: 'set null',
        }),
        createdAt: timestamp('created_at').notNull(),
        updatedAt: timestamp('updated_at').notNull(),
      },
      (table) => ({
        tenantIdx: index('user_tenant_idx').on(table.tenantId),
        roleIdx: index('user_role_idx').on(table.role),
      }),
    );

    export const session = pgTable('session', {
      id: text('id').primaryKey(),
      userId: text('user_id')
        .notNull()
        .references(() => user.id, { onDelete: 'cascade' }),
      token: text('token').notNull().unique(),
      expiresAt: timestamp('expires_at').notNull(),
      ipAddress: text('ip_address'),
      userAgent: text('user_agent'),
      createdAt: timestamp('created_at').notNull(),
      updatedAt: timestamp('updated_at').notNull(),
    });

    export const account = pgTable('account', {
      id: text('id').primaryKey(),
      userId: text('user_id')
        .notNull()
        .references(() => user.id, { onDelete: 'cascade' }),
      accountId: text('account_id').notNull(),
      providerId: text('provider_id').notNull(),
      accessToken: text('access_token'),
      refreshToken: text('refresh_token'),
      accessTokenExpiresAt: timestamp('access_token_expires_at'),
      refreshTokenExpiresAt: timestamp('refresh_token_expires_at'),
      scope: text('scope'),
      idToken: text('id_token'),
      password: text('password'),
      createdAt: timestamp('created_at').notNull(),
      updatedAt: timestamp('updated_at').notNull(),
    });

    export const verification = pgTable('verification', {
      id: text('id').primaryKey(),
      identifier: text('identifier').notNull(),
      value: text('value').notNull(),
      expiresAt: timestamp('expires_at').notNull(),
      createdAt: timestamp('created_at').notNull(),
      updatedAt: timestamp('updated_at').notNull(),
    });
    ```

       ```typescript
       import { db } from './index';
       import { tenants, tenantDomains, branches } from './schema';

       async function seed() {
         const existingTenants = await db.select().from(tenants);
         if (existingTenants.length > 0) {
           console.log('Seed data already exists, skipping...');
           return;
         }
         
         const [indiaTenant] = await db.insert(tenants).values({
           name: 'Gajan Traders India',
           slug: 'gajan-india',
         }).returning();
         
         const [sriLankaTenant] = await db.insert(tenants).values({
           name: 'Gajan Traders Sri Lanka',
           slug: 'gajan-sri-lanka',
         }).returning();

           { domain: 'india.gajantraders.com', tenantId: indiaTenant.id },
           { domain: 'srilanka.gajantraders.com', tenantId: sriLankaTenant.id },
         ]);

           { name: 'Mumbai HQ', tenantId: indiaTenant.id },
           { name: 'Colombo HQ', tenantId: sriLankaTenant.id },
         ]);
         
         console.log('Seed data inserted successfully');
       }
       
       seed().catch(console.error);
       ```
