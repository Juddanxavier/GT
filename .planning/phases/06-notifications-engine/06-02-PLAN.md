# 06-02: Trigger Integration — Map 17TRACK Events → Notification Queue

## Objective

Hook into the tracking update pipeline so that when a major tracking event arrives, a notification job is enqueued. Map 17TRACK event tags to the 5 major transition types, look up the customer, and fan out to the notification queue.

## Context

- Tracking events arrive via webhook handler (`/api/tracking/webhook`) and polling fallback
- Events are upserted into `tracking_event` table via the update worker
- `notificationQueue` already exists in queues but is unused
- `notificationWorker` is a placeholder

## Tasks

### Task 2.1: Define major event mapping

**Action:**
1. Create `apps/api/src/notifications/event-map.ts`:
```typescript
// 17TRACK event tags mapped to notification-worthy transitions
// Reference: https://docs.17track.net/en/apiv3/tracking-data-model

const MAJOR_EVENTS = new Set([
  'InfoReceived',     // Shipment created / picked up
  'InTransit',        // Moving through network
  'OutForDelivery',   // Out for delivery
  'Delivered',        // Delivered
  'Exception',        // Delivery exception / issue
]);

export function isMajorEvent(tag: string): boolean {
  return MAJOR_EVENTS.has(tag);
}

// Tag normalization — 17TRACK may return variations
const TAG_ALIASES: Record<string, string> = {
  'Pickup': 'InfoReceived',
  'PickedUp': 'InfoReceived',
  'Accepted': 'InfoReceived',
  'OnTransit': 'InTransit',
  'Arrived': 'InTransit',
  'Dispatch': 'InTransit',
  'OutForDelivery': 'OutForDelivery',
  'CarrierDelivered': 'Delivered',
  'Signed': 'Delivered',
  'DeliveryFailure': 'Exception',
  'DeliveryIssue': 'Exception',
  'ReturnToSender': 'Exception',
};

export function normalizeTag(rawTag: string): string | null {
  const tag = TAG_ALIASES[rawTag];
  if (tag && MAJOR_EVENTS.has(tag)) return tag;
  if (MAJOR_EVENTS.has(rawTag)) return rawTag;
  return null;
}
```

**Verify:** Unit test: `normalizeTag('Pickup')` → `'InfoReceived'`, `normalizeTag('InTransit')` → `'InTransit'`, `normalizeTag('NotFound')` → `null`.

### Task 2.2: Create notification service

**Action:**
1. Create `apps/api/src/notifications/service.ts`:
```typescript
import { notificationQueue } from '../queues';
import { normalizeTag, isMajorEvent } from './event-map';

type TrackingEvent = {
  id: string;
  shipmentId: string;
  tag: string;
  description?: string;
  occurredAt: string;
  location?: string;
};

type ShipmentInfo = {
  id: string;
  trackingNo: string;
  carrier?: string;
  origin?: string;
  destination?: string;
  estimatedDelivery?: string;
  status: string;
  customer?: {
    name?: string;
    email?: string;
    phone?: string;
  };
  tenantId: string;
};

export async function handleTrackingEvent(
  event: TrackingEvent,
  shipment: ShipmentInfo,
): Promise<void> {
  const normalizedTag = normalizeTag(event.tag);
  if (!normalizedTag || !isMajorEvent(normalizedTag)) {
    return; // Skip minor events
  }

  if (!shipment.customer?.email && !shipment.customer?.phone) {
    return; // No contact info to notify
  }

  if (!notificationQueue) {
    console.warn('[notifications] Redis not available — skipping notification');
    return;
  }

  await notificationQueue.add('notify', {
    shipmentId: shipment.id,
    eventId: event.id,
    eventType: normalizedTag,
    tenantId: shipment.tenantId,
  });
}
```

2. The queue stores just enough to trigger processing — the worker will load full details from DB.

## Threat Model

| Threat ID | Component | Risk | Mitigation |
|-----------|-----------|------|------------|
| T-06-02-01 | Event mapping too broad | Minor events trigger notifications | `isMajorEvent` whitelist — only 5 event types pass |
| T-06-02-02 | Missing customer | Crash on null customer | Guard clause on `!shipment.customer` |
| T-06-02-03 | Queue overload on burst | Webhook storm | BullMQ concurrency=5 + rate limiter (3 req/s default) |

## Success Criteria

1. ✅ Major events (`InfoReceived`, `InTransit`, `OutForDelivery`, `Delivered`, `Exception`) enqueue notification jobs
2. ✅ Minor events are silently filtered out
3. ✅ Customers without email/phone are skipped
4. ✅ `notificationWorker` processes jobs, looks up shipment, enqueues email job
5. ✅ Graceful degradation when Redis is unavailable
