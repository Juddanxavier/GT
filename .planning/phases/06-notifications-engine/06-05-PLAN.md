# 06-05: Admin Notification Settings UI

## Objective

Provide a settings page in the admin app where tenant admins can configure notification preferences: email sender addresses, WhatsApp sender numbers, and branding assets (logo, company name) used in templates.

*Note: This is the least critical wave. All notification functionality works without this UI — settings are configured via env vars. This wave adds self-service configuration in the admin panel.*

## Tasks

### Task 5.1: Create notification settings DB table

**Action:**
1. Add to Drizzle schema (`apps/api/src/db/schema.ts`):

```typescript
export const tenantSettings = pgTable('tenant_settings', {
  tenantId: uuid('tenant_id').references(() => tenant.id).notNull().primaryKey(),
  emailFromName: varchar('email_from_name', { length: 255 }),
  emailFromEmail: varchar('email_from_email', { length: 255 }),
  whatsappSender: varchar('whatsapp_sender', { length: 50 }),
  logoUrl: text('logo_url'),
  primaryColor: varchar('primary_color', { length: 7 }).default('#006FEE'),
  companyName: varchar('company_name', { length: 255 }),
  updatedAt: timestamp('updated_at').defaultNow().notNull(),
});
```

2. Generate and apply migration.

### Task 5.2: Create settings API routes

**Action:**
1. Create `apps/api/src/routes/settings.ts`:
   - `GET /api/settings/notifications` — Get current tenant's notification settings
   - `PATCH /api/settings/notifications` — Update settings (tenant-admin+ only)

2. Register in `apps/api/src/index.ts`.

### Task 5.3: Create admin settings page

**Action:**
1. Create `apps/admin/app/(dashboard)/settings/notifications/page.tsx`:
   - Form fields: Email sender name/address, WhatsApp sender number, logo URL, primary color picker, company name
   - Preview section showing how email templates look with current branding
   - Save button → PATCH to settings API
   - Toast on success/failure

2. Add "Settings → Notifications" link in sidebar.

### Task 5.4: Wire branding into email rendering

**Action:**
1. Update `loadTenantBranding` in the notification worker to read from `tenant_settings` table (with Redis cache fallback to env defaults).
2. Cache result with tenant-prefixed key (`t:{tenantId}:branding`) for 5 minutes.

### Task 5.5: Verification

**Action:**
1. Open settings page → verify form loads with current values
2. Update logo URL → verify next email uses new logo
3. Verify tenant-admin can update; staff cannot (403)
4. Verify env vars serve as defaults when no DB row exists

## Success Criteria

1. ✅ Tenant admins can configure email sender and branding via admin UI
2. ✅ Branding is reflected in sent emails
3. ✅ Staff are blocked from editing settings (read-only view or 403)
4. ✅ Env var defaults work when DB settings are absent
