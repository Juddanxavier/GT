# 06-03: Idempotency + Dead Letter Queue + Sentry Alerting

## Objective

Prevent duplicate notifications from webhook replays, and ensure failed notifications after 3 retries go to a dead letter queue with Sentry alerting.

## Context

- BullMQ already has `attempts: 3` and `backoff: { type: 'exponential', delay: 2000 }` in defaultJobOptions
- BullMQ automatically moves jobs to "failed" after exhausting retries
- BullMQ supports "dead letter" pattern via `removeOnFail: { age: 86400, count: 500 }` + separate monitoring
- Redis is available for idempotency key storage (TTL-based expiry)

## Tasks

### Task 3.1: Redis-based idempotency store

**Action:**
1. Create `apps/api/src/notifications/idempotency.ts`:

```typescript
import { redis } from '../redis';

const IDEMPOTENCY_TTL = 7 * 24 * 3600; // 7 days in seconds

/**
 * Check if a notification has already been sent for this event+shipment+channel.
 * If not, mark it as sent atomically.
 */
export async function checkAndSetIdempotency(
  eventId: string,
  shipmentId: string,
  channel: 'email' | 'whatsapp',
): Promise<boolean> {
  if (!redis) {
    // No Redis — skip dedup but log warning
    console.warn('[idempotency] Redis not available, skipping dedup');
    return false;
  }

  const key = `idempotent:${channel}:${shipmentId}:${eventId}`;

  // SET NX: only succeeds if key doesn't exist
  const result = await redis.set(key, '1', {
    NX: true,
    EX: IDEMPOTENCY_TTL,
  });

  // If result is null, key already existed → duplicate
  return result === null;
}

/**
 * For testing: clear an idempotency key
 */
export async function clearIdempotency(
  eventId: string,
  shipmentId: string,
  channel: 'email' | 'whatsapp',
): Promise<void> {
  if (!redis) return;
  const key = `idempotency:${channel}:${shipmentId}:${eventId}`;
  await redis.del(key);
}
```

**Verify:** Call `checkAndSetIdempotency('e1', 's1', 'email')` → `false` (first call). Call again → `true` (duplicate). Clear → call again → `false`.

### Task 3.4: Sentry alerting on DLQ

**Action:**
1. Create `apps/api/src/workers/dlq-monitor.ts`:

```typescript
import { Worker } from 'bullmq';
import { bullConnection } from '../redis';
import * as Sentry from '@sentry/hono';

export function startDlqMonitor(): void {
  if (!bullConnection) return;

  const worker = new Worker(
    'dead-letter',
    async (job) => {
      // DLQ jobs are monitored, not processed
      Sentry.captureMessage(
        `[DLQ] Job ${job.name} (${job.id}) failed after retries`,
        'warning',
      );
      Sentry.setTags({
        'dlq.jobName': job.name,
        'dlq.originalQueue': job.data?.queueName ?? 'unknown',
        'dlq.failedReason': job.failedReason ?? 'unknown',
      });
    },
    { connection: bullConnection, concurrency: 1 },
  );

  worker.on('completed', (job) => {
    console.error(`[DLQ] Job ${job?.id} moved to dead letter queue and reported to Sentry`);
  });
}
```

2. Call `startDlqMonitor()` in `apps/api/src/index.ts` after workers are initialized.

**Verify:** Force a notification job failure → Sentry captures a `[DLQ]` message with tags.

## Threat Model

| Threat ID | Category | Component | Mitigation |
|-----------|----------|-----------|------------|
| T-06-03-01 | Duplicate notifications | Idempotency keys | Redis SET NX with 7-day TTL prevents replay within window |
| T-06-03-02 | Lost failure visibility | DLQ | All permanently failed jobs go to DLQ + Sentry alert |
| T-06-03-03 | Redis outage | Idempotency check | Graceful fallback: skip dedup, log warning, allow (rare) duplicates |

## Success Criteria

1. ✅ Duplicate events within 7 days are idempotently suppressed
2. ✅ Jobs that exhaust 3 retries land in the dead letter queue
3. ✅ Sentry captures a `[DLQ]` event for each permanently failed job
4. ✅ Bull Board shows the DLQ with failed job details
5. ✅ Redis outage does not crash the worker — dedup degrades gracefully
