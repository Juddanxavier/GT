## Objective

Let staff/admins open any customer and see that customer's shipments and invoices in one place.

## Tasks

### 8.1.1 API: `userId` filter on invoice list

- `apps/api/src/routes/invoices.ts` GET `/` handler (line ~142): read `userId` query param, add `eq(invoices.userId, userId)` to the conditions (alongside existing search/status filters), keep tenant/branch scope.
- Only for roles that can already read invoices (list requires tenant scope; keep `requireRole` as-is).
- Cache key: append `:${userId ?? 'all'}`.
- Tests: `apps/api/src/routes/invoices.test.ts` — filter returns only that user's invoices; unauthorized tenant can't see other tenant's invoices via `userId` (tenant isolation still enforced by scope).

### 8.1.2 Customer profile page

- New `apps/admin/app/(dashboard)/customers/[id]/page.tsx`:
  - Header: name, email, phone (flag + dial code), branch name, role chip, edit link.
  - Data: user detail via existing users fetch (`useUsers`/`useUser` if present) or a direct `api.get(/api/users/:id)`; resolve branch via `useBranches`.
  - Shipments: `useShipments(page, limit, 'all', '')` + pass `customerId` — add an optional `customerId` param to the hook (the API already accepts it).
  - Invoices: new/updated `useInvoices` hook with `userId` filter (API from 8.1.1).
  - Tables: reuse `Table` pattern from customers page (with `Table.Content`, `isRowHeader`). Rows link to `/shipments/[id]` / `/invoices/[id]`.
  - States: loading skeleton, empty state, error retry.

### 8.1.3 Wire navigation

- Customers table: make row action / name cell link to `/customers/{id}` (keep edit link as-is).
- Verify profile page is reachable for `staff`, `tenant-admin`, `superadmin`.
