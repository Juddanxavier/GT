## Objective

Replace the current CustomerAssigner (Lookup button → result) with a search-as-you-type autocomplete that suggests customers, plus inline email/phone fields for walk-in scenarios.

## Tasks

### 2.1 Build customer search API endpoint

- Add `GET /api/customers/search?q=...` — lightweight endpoint (or reuse existing customer list with search filter).
- Returns `{ id, name, email, phone }[]` matching by name, email, or phone.
- Scoped by tenant (current middleware stack).
- Limit results to 20, no pagination needed.
- Cache with short TTL (30s).

### 2.2 Rewrite CustomerAssigner component

- Replace `apps/admin/components/customer-assigner.tsx`.
- Layout:
  - **Autocomplete field**: As admin types, show dropdown of matching customers (name, email/phone subtitle). Debounce 300ms. Powered by new search endpoint.
  - **Email/Phone fields**: Below autocomplete, shown when no customer is selected from dropdown. Pre-filled from customer profile if one is selected.
  - **Lookup button removed** — matching is instant via autocomplete.
- States:
  - **No customer selected**: Show autocomplete input + email/phone fields for manual entry.
  - **Customer selected from dropdown**: Show "Linked" card (current style) with option to override email/phone.
  - **Emails/phones entered manually** (no matching customer): Show "Unassigned — will be claimable via portal" hint.
  - **Override active**: Show a small indicator that contact info differs from customer profile.
- Props: keep same interface for backward compat with parent.
- Loading state for search (spinner in dropdown).

### 2.3 Update create modal integration

- Update `apps/admin/app/(dashboard)/shipments/page.tsx`:
  - Wire new CustomerAssigner to the create form.
  - Payload: `{ customerId: uuid | null, contactEmail: string, contactPhone: string }`.
  - Keep existing "Self" option logic.
- Remove `errors.carrier` reference (already removed carrier field).
