## Objective

Redesign the claim experience in the customer portal so unassigned shipments can be claimed easily with a polished UX.

## Tasks

### 4.1 Update tracking page for unassigned shipments

- Current public track page (`apps/customer/app/track/page.tsx` or similar) shows tracking info.
- If shipment has no `userId` (unassigned), show a prominent "Is this your shipment? Claim it" CTA.
- CTA opens a claim flow. Options:
  - **Email OTP**: Enter email → receive OTP → verify → claim.
  - **Phone OTP**: Enter phone → receive OTP → verify → claim (if phone on record).
- Show masked contact info: "We'll send a code to j***@example.com" to reassure the user.

### 4.2 Build claim UI components

- `apps/customer/components/claim-flow.tsx` — multi-step component:
  - Step 1: "Verify your identity" — choose email or phone verification.
  - Step 2: Enter OTP code (6 digits, with resend timer).
  - Step 3: Success — "Shipment claimed! You'll now receive tracking updates."
- Loading states for OTP send/verify.
- Error states for invalid OTP, expired OTP, network failure.
- Empty state if no contact info on the shipment ("Contact the sender to update your contact info").

### 4.3 Post-claim flow

- After successful claim: redirect to portal dashboard (`/dashboard`) with a success banner.
- Dashboard should immediately show the claimed shipment in the list.
- If customer doesn't have an account yet (first-time claim):
  - Create user account (existing `claim-shipment.ts` logic handles this).
  - Set a random password.
  - On success, optionally offer to set a password: "Create your account password to log in later."

### 4.4 Polish existing claim API

- Review `apps/api/src/routes/claim-shipment.ts`:
  - OTP email template: improve HTML styling, add brand logo/colors.
  - Rate-limit OTP requests per tracking number (e.g., 3 attempts per 10 min).
  - Return user-friendly error messages from OTP failures.
  - Add a `POST /api/track/claim/resend-otp` endpoint (reuses same OTP if still valid, otherwise generates new one).

### 4.5 Add claim history/audit

- Log each claim attempt and success to audit log.
- Show claim history in admin shipment detail view (optional — stretch goal).
