# 08-02: Socket.IO Wiring — Server + Client

## Goal

Wire the existing `realtime.ts` server into the HTTP server so Socket.IO actually starts, install `socket.io-client` in the admin app, and emit `dashboard:update` events from key routes so the dashboard refreshes in real-time.

## Files Changed

| File | Action |
|------|--------|
| `apps/api/src/index.ts` | Edit — capture HTTP server, call `createRealtimeServer` |
| `apps/api/src/realtime.ts` | Edit — export types, ensure emit functions are accessible |
| `apps/api/src/routes/shipments.ts` | Edit — emit `dashboard:update` on create/update/delete |
| `apps/api/src/routes/invoices.ts` | Edit — emit `dashboard:update` on create/send |
| `apps/api/src/routes/webhooks.ts` | Edit — emit `dashboard:update` on tracking event insert |
| `apps/api/src/routes/dashboard.ts` | Edit — emit `dashboard:update` on stats fetch (optional heartbeat) |
| `apps/admin/package.json` | Edit — add `socket.io-client` dependency |
| `apps/admin/src/lib/socket.ts` | **Create** — Socket.IO client singleton with auto-reconnect |

## Detail

### Server-side wiring (`index.ts`)

Current code:
```ts
const server = serve({ fetch: app.fetch, port: ... });
```

Change to:
```ts
const server = serve({ fetch: app.fetch, port: ... });
const { createRealtimeServer } = await import('./realtime.js');
createRealtimeServer(server);
```

`createRealtimeServer` already exists in `realtime.ts` — just needs to be called with the HTTP server. No signature changes needed.

### Emit points

Import in each route file:
```ts
import { emitToTenant } from '../realtime';
```

| Route | Event | When |
|-------|-------|------|
| `POST /api/shipments` (create) | `dashboard:update` | After successful insert |
| `PATCH /api/shipments/:id` (update) | `dashboard:update` | After successful update |
| `DELETE /api/shipments/:id` (delete) | `dashboard:update` | After successful delete |
| `POST /api/invoices/shipment/:shipmentId` (create) | `dashboard:update` | After insert |
| `POST /api/invoices/:id/send` (send) | `dashboard:update` | After email count update |
| `POST /webhooks/17track` (event) | `dashboard:update` | After tracking event dedup+insert (non-blocking) |

Emit pattern:
```ts
// Fire-and-forget — never block the response
emitToTenant(tenantId, 'dashboard:update', {}).catch(console.error);
```

The `{}` payload is intentionally empty — the client re-fetches stats on receiving the event (avoids stale data race conditions).

### Client-side (`lib/socket.ts`)

```ts
import { io, type Socket } from 'socket.io-client';

const SOCKET_URL = process.env.NEXT_PUBLIC_API_URL || 'http://localhost:3001';

let socket: Socket | null = null;

export function getSocket(): Socket | null { return socket; }

export function connectSocket(tenantId: string): Socket {
  if (socket?.connected) return socket;
  socket = io(SOCKET_URL, {
    query: { tenantId },
    transports: ['websocket', 'polling'],
    reconnection: true,
    reconnectionDelay: 2000,
    reconnectionAttempts: 10,
  });
  return socket;
}

export function disconnectSocket(): void {
  socket?.disconnect();
  socket = null;
}
```

### Dashboard integration

In dashboard `page.tsx`:
```ts
useEffect(() => {
  if (!session?.user?.tenantId) return;
  const socket = connectSocket(session.user.tenantId);
  socket.on('dashboard:update', () => { refreshStats(); });
  return () => { socket.off('dashboard:update'); };
}, [session]);
```

### Graceful degradation

- Socket.IO connection failure → dashboard still works on page load/reload
- No UPSTASH_REDIS_URL → `realtime.ts` already handles this (returns stub functions that log and no-op)
- `admin/lib/socket.ts` returns null if connection fails; dashboard code checks `socket?.on()`
