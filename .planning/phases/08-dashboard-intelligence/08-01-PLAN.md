# 08-01: KPI Data API + Exception Engine

## Goal

Single `GET /api/dashboard/stats` endpoint that returns all aggregated KPI data, including exception/stale detection, so the dashboard has everything it needs in one round-trip.

## Files Changed

| File | Action |
|------|--------|
| `apps/api/src/routes/dashboard.ts` | **Create** — stats endpoint |
| `apps/api/src/index.ts` | Edit — register dashboard routes |

## Role-Based Data Scoping

Use `queryScope` from `@repo/permissions` to determine filters:

```ts
import { queryScope, type PermissionContext } from '@repo/permissions';

const user = c.get('user') as PermissionContext;
const scope = queryScope(user);
// scope: { tenantId?, branchId? }
// superadmin: {} (no filter — sees all)
// tenant-admin: { tenantId: '...' } (org-wide)
// staff: { tenantId: '...', branchId: '...' } (branch-scoped)
```

**Tenant-admin** can optionally pass `?branchId=` to drill into a specific branch. **Staff** ignores any `?branchId=` param — always scoped to their own branch.

All SQL queries apply `scope.tenantId` and `scope.branchId` where applicable.

### `GET /api/dashboard/branches` (for tenant-admin only)

Returns list of branches for the tenant's org, used to populate branch filter dropdown:

```json
{
  "data": [
    { "id": "...", "name": "Chennai HQ" },
    { "id": "...", "name": "Mumbai Office" }
  ]
}
```

Middleware: `requireRole('tenant-admin', 'staff')`. Scoped to user's tenantId.

## Stale Detection

- `stale`: status NOT IN (`delivered`, `expired`) AND `lastTrackedAt` < NOW() - INTERVAL '72 hours'
- `overdue`: status NOT IN (`delivered`, `expired`) AND `estimatedDelivery` < NOW() - INTERVAL '24 hours'
- `notTracked`: `trackingRegistered` = false AND `createdAt` < NOW() - INTERVAL '24 hours'

## Queries (tenant-admin/staff)

All queries filter by `scope.tenantId` and optionally `scope.branchId`.

1. `SELECT status, COUNT(*) FROM shipments WHERE tenantId = $1${branchId ? ' AND branchId = $2' : ''} GROUP BY status`
2. `SELECT DATE(createdAt) as date, COUNT(*) FROM shipments WHERE ... AND createdAt > NOW() - INTERVAL '14 days' GROUP BY date ORDER BY date`
3. `SELECT carrier, COUNT(*) FROM shipments WHERE ... AND carrier IS NOT NULL GROUP BY carrier ORDER BY count DESC`
4. `SELECT COUNT(*), SUM(CASE WHEN isActive THEN 1 ELSE 0 END) FROM customers WHERE ...`
5. `SELECT COUNT(*), SUM(CASE WHEN status = 'converted' THEN 1 ELSE 0 END) FROM quotations WHERE ...`
6. `SELECT COUNT(*), COALESCE(SUM(CAST(amount AS numeric)), 0), COALESCE(SUM(CAST(amount AS numeric)) FILTER (WHERE paidAt >= date_trunc('month', NOW())), 0) FROM invoices WHERE ...`
7. Alerts: SELECT shipments matching stale/overdue/exception conditions, limit 20

## Queries (superadmin — cross-tenant)

1. Same as above but WITHOUT tenantId/branchId filters
2. `SELECT t.id, t.name, COUNT(s.*), COUNT(s.*) FILTER (WHERE s.status = 'in_transit'), ... FROM tenant t LEFT JOIN shipment s ON s.tenant_id = t.id GROUP BY t.id, t.name` — per-tenant breakdown
3. `SELECT DATE(s.createdAt), COUNT(*) FROM shipments s WHERE ... GROUP BY date` — cross-tenant perDay

## Null Safety

- `carrier` can be null — `WHERE carrier IS NOT NULL` on byCarrier query
- `CAST(amount AS numeric)` for `numeric` column joins/sums
- `estimatedDelivery` can be null — `WHERE estimatedDelivery IS NOT NULL` on overdue check

## Verification

```bash
curl -s http://localhost:3001/api/dashboard/stats \
  -H "Cookie: <session>" \
  -H "X-Tenant-ID: <tenantId>" | jq .
```

All counts should match manual queries. Stale/overdue counts should be 0 for fresh data.
